## 方向性转向

继续只增加规则会把项目带向“复杂桌游规则引擎”。最终目标需要三层分工：

1. 世界约束层  
   资源、空间、路线、制度、身体需求、行动可行性和状态结算。它必须确定、可测试，并保留足够的审计记录。

2. 生成式 agent 层  
   身份、目标、记忆、反思、对话、计划、关系解释和局部社会策略。它可以由 LLM 驱动，但输出必须是结构化意图，由世界约束层验证。

3. 评估和观察层  
   长跑稳定性、社会可信度、角色连续性、局部影响、干预响应和用户可理解性。

## M14: Generative Society Alpha

目标不是最小 demo，而是一个完整 Alpha 切片。它必须在小规模内像一个社会，而不是像几个脚本角色。

验收标准：

- 12 个 agent，有稳定身份、长期目标、价值偏好、关系和组织归属。
- 每个 agent 有结构化记忆流，可按重要性、相关性和时间检索。
- 每 7 天生成一次反思，影响后续计划上下文。
- 每天按“观察 -> 检索记忆 -> 计划 -> 行动 -> 记录事件 -> 反思”推进。
- 发生社交事件时能形成双向记忆，对关系和后续计划产生影响。
- 观察器能看到 agent 的目标、最新反思、计划、组织和地点状态。
- 30 天运行能生成 JSON/HTML 报告，并展示至少一个用户可感知的社会变化。
- 没有真实 API key 时使用确定性 provider 和 Codex CLI debug provider；需要批量 LLM 时再接 OpenAI API。

当前 M14 已经完成 Alpha 的第一版可运行闭环。下一步不是继续扩大人口，而是增强社会行为质量：冲突、规范分歧、谣言传播、组织提案和干预后的长期记忆。

## M15: Evaluation Harness

- 增加“社会可信度”评估，不只看资源是否崩溃。
- 评估维度包括角色连续性、记忆使用率、干预响应、冲突后恢复、组织行为一致性。
- 引入固定场景测试：饥荒、路线中断、新移民、谣言广播、组织分裂。
- 每个版本至少跑 5 seed、30 天和 365 天两个尺度。

## M16: LLM Batch Integration

- 接入并实测 OpenAI API provider。
- 引入批处理、缓存、预算、失败降级和 prompt 版本记录。
- LLM 不直接写世界状态，只输出结构化计划、对话、反思或制度提案。
- 保留 deterministic/debug replay 能力: 同一次运行应能保存关键 LLM 输入输出，以便调试、回归和局部解释，但不承诺完整重建社会因果。

## M17: Multi-Settlement Society

- 从单聚落扩展到两个以上聚落。
- 引入跨聚落迁移、贸易、拒绝交易、联盟、竞争和信息传播。
- 这一步才适合继续扩展大型地图和更完整 3D 体验。

## 当前下一步

先完成 M14 的 agent 生成式架构，而不是继续 M12g 的多聚落规则扩展。原因是：如果 agent 层还没有记忆、反思、对话和意图，跨聚落只会制造更多硬编码规则。
