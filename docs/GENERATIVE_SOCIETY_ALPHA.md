# Generative Society Alpha

M14 的目标是做出一个完整 Alpha 切片：小规模，但闭环完整；不是最小 demo，也不是只增加规则。

## 产品呈现目标

最终产品应该像一个“可进入、可观察、可参与、可影响的生成式 3D 开放虚拟社会”。

第一屏不是说明书，而是一个活着的社会：

- 3D 场景中能看到地点、路线、组织、资源和 agent。
- 点击 agent 能看到身份、目标、关系、记忆、计划和反思。
- 用户可以注入资源、灾害、广播、制度、组织或新成员。
- 社会不会按预设剧情分支走，而是在约束和 agent 推理中演化。
- 每次运行都有历史、指标、事件记录和可观察的局部影响。

## M14 完成定义

M14 完成时必须具备：

- 12 个 agent。
- 至少 2 个组织和 5 个地点。
- 结构化记忆流。
- 记忆检索进入计划上下文。
- 周期反思进入后续上下文。
- 社交行动形成可见关系变化和记忆。
- 30 天运行可输出 HTML 报告。
- 观察器可查看目标、最新反思、计划和组织。
- 多 seed 短跑通过，365 天长跑不崩溃。

## 当前 Alpha 状态

已实现：

- `generative_alpha` 预设：12 个 agent、8 个组织、8 个地点。
- agent 身份档案、长期目标、价值偏好。
- 事件转结构化记忆。
- 记忆检索进入认知上下文。
- 每 7 天反思。
- 社交行动生成 `dialogue` 事件，并让双方形成记忆。
- 社会可信度评估：记忆覆盖、反思覆盖、对话密度、组织参与、信任饱和风险。
- Alpha 风暴压力测试：`scenarios/generative-alpha-storm.json`。
- OpenAI provider 代码边界，等待 API key 后启用。

仍需增强：

- 冲突和规范分歧。
- 谣言和信息传播。
- agent 提出组织或制度变更。
- 对话内容由 LLM 生成，而不是确定性模板。
- 用于调试和评估的 LLM 输入输出缓存。

## 用户可见场景

推荐 Alpha 演示场景：

1. 正常运行 14 天，观察角色形成稳定工作和社交节奏。
2. 第 15 天施加风暴，损坏资源和安全感。
3. 第 16 天广播一条救援或恐慌信息。
4. 继续运行到第 30 天。
5. 报告中能看到谁记住了危机、谁改变了计划、哪个组织承担修复、关系是否改善或恶化。

## 不再接受的完成标准

- 只新增一个规则参数。
- 只新增一个角色动作。
- 只让指标更稳定但看不出社会行为。
- 只展示漂亮 3D 画面但看不到 NPC 记忆、关系和用户影响。
- 只让 LLM 聊天但不能影响世界。

M14 之后，每个里程碑必须同时交付：

- 一个新社会能力。
- 一个观察入口。
- 一个测试或评估。
- 一个可运行 artifact。
